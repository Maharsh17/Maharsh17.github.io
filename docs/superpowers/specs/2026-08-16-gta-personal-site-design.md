# GTA San Andreas Personal Website - Design

**Date:** 2026-08-16
**Status:** Awaiting review
**Author:** Maharsh Jani (design assisted)

## Summary

Turn the combined GTA San Andreas web recreation at `gta-web/combined-gta/`
into Maharsh Jani's personal website, using the game's save-file screen as the
organizing metaphor. Every page stays in GTA chrome (full commitment). All
content derives from real sources: the resume PDF, the GitHub API, and
hand-authored files the owner controls.

## Goals

1. A personal site memorable enough to be worth showing, readable enough for a
   recruiter skimming for 30 seconds.
2. Zero invented content. Every number traces to a real source.
3. Static files only. No build system, no server, no CI.
4. Preserve the visual fidelity of the four fan-made recreations already
   combined in `combined-gta/`.

## Non-Goals

- Shipping any asset extracted from the retail game install.
- A CMS, a blog engine, or anything that needs a runtime.
- Replacing `janimaharsh.com` (that stays whatever it currently is).

## Audience and Tone

Between "for fun" and "for recruiters". The theme is the differentiator, so it
commits fully rather than acting as a splash screen. The constraint that keeps
it useful: the most obvious button on the main menu leads to the work.

## Architecture

Static multi-page site. Each page is its own HTML document loading only its own
stylesheet. This is load-bearing rather than stylistic: `gtasamenu.css` and
`gtasa-page.css` both define `.container` incompatibly (grid versus flex), so
one document per project is what guarantees the recreations render identically.

```
combined-gta/
  index.html          Main menu
  loadgame.html       Projects as save slots
  stats.html          Skills as stat bars
  missions.html       Experience as mission log
  map.html            Places
  hud.html            Current status
  options.html        Contact and links
  data/
    projects.json     Generated by gh api. Never hand-edited.
    overrides.json    Hand-authored. Generator never touches it.
  assets/{menu,stats,notify,hud}/
  js/site.js
```

## Data Model

### projects.json (generated)

One `gh api graphql` call writes this file. Regenerated by rerunning the
command; never edited by hand.

```json
{
  "generated": "2026-08-16",
  "repos": [
    {
      "nameWithOwner": "InviteInstitute/lm-dashboard",
      "pushedAt": "2026-08-10",
      "isArchived": false,
      "isPrivate": false,
      "description": "Realtime LM Dashboard for Intervention Studies",
      "languages": [{"name": "Python", "size": 184320}]
    }
  ]
}
```

### overrides.json (hand-authored)

Everything the API cannot know. The owner writes this; tooling never
overwrites it.

```json
{
  "InviteInstitute/lm-dashboard": {
    "slotName": "LM DASHBOARD",
    "blurb": "One sentence, in your voice.",
    "status": "active",
    "hidden": false
  }
}
```

### The Status Field

No completion percentages. Invented numbers are the failure mode this design
exists to avoid. Status collapses to three labels derived from facts the API
reports:

| Label | Derived from |
|---|---|
| `shipped` | Has a release, or archived while complete |
| `active` | `pushedAt` within the last 90 days |
| `archived` | `isArchived` is true |

An override may set the label explicitly. It may not set a number.

## Page Designs

### loadgame.html - Save Slots

The page `load game` points at, so it carries the most weight. GTA San Andreas
caps saves at 8 slots, which is a convenient and thematically honest ceiling.

Each slot shows: slot number, project name, **last saved** (real last-commit
date), primary language, and status label. Private repos appear as slots with
no outbound link rather than being hidden, so the picture stays complete.

Initial eight, all real:

1. `InviteInstitute/lm-dashboard` - public, Python, active
2. `InviteInstitute/vex-agent-integration` - public, Python, active
3. `InviteInstitute/agent-lm-packages` - public, Python
4. `Maharsh17/county-clustering` - public, Python
5. `CS222-UIUC/fa25-team118-titans` - public, real-time collaborative editor
6. FireWatch (Illinois WCS DevAda) - no public repo, slot from resume content
7. `Maharsh17/resume-blaster` - private, TeX
8. `HarshithaS2023/ai4all` - public, HTML

### stats.html - Skill Bars

Reuses the existing `gtasa-stats` markup and CSS unchanged. Nothing claims
proficiency.

Bar fill is **the fraction of projects a language appears in**, not the share
of bytes written in it.

This was changed during planning after running the real numbers. Byte share
produced "94% HTML", because `HarshithaS2023/ai4all` alone contributes
16.69 MB of the 16.70 MB total HTML, almost certainly generated or vendored
output in a repo Maharsh only collaborates on. A single such file swamps every
other signal, so byte share is technically true and materially false.

Project coverage is outlier-resistant: one enormous generated file counts once,
the same as one small handwritten one. Verified output across the eight slots:

| Language | Coverage |
|---|---|
| Python | 5/7 |
| HTML | 4/7 |
| CSS, Dockerfile, JavaScript, Shell | 3/7 |
| Makefile | 2/7 |
| PLpgSQL, TeX | 1/7 |

The page states the denominator in plain words, so the bar is self-explaining
rather than a number the reader has to trust.

Grouping follows the resume's own four categories: Languages; Web and
Real-Time; Data and Intelligence; Production.

### missions.html - Mission Log

Experience from the resume, chronological, in GTA mission-briefing framing.
Titles in BankGothic, body prose in a readable face. Four entries:

- NSF AI INVITE Institute, Software Engineer, Dec 2025 to present
- Illinois Women in CS DevAda, Lead Software Engineer, Jan 2026 to present
- Student Alumni Ambassadors, VP Alumni Relations, Mar 2026 to present
- Management Leadership for Tomorrow, Career Prep Fellow, Jan 2026 to present

Bullet text comes from the resume verbatim or lightly condensed. Not rewritten
into new claims.

### options.html - Contact

Email `majani2@illinois.edu`, LinkedIn `janimaharsh`, GitHub `Maharsh17`,
website `janimaharsh.com`.

**The phone number from the resume is deliberately omitted.** A PDF someone
opens is a different exposure from a themed page a search engine indexes.

## Typography

Full commitment does not mean body text in BankGothic. The game itself uses
three faces, and the site follows that split:

Corrected during planning after reading the actual CSS. An earlier draft of
this table named Pricedown for titles, which is wrong: the recreation uses
Beckett there, and Pricedown appears only in the React HUD.

| Role | Face | Where it already lives |
|---|---|---|
| Page titles | Beckett | `.menu-title` in `gtasamenu.css` |
| Menu options, labels | BankGothic | `.menu-option` in `gtasamenu.css` |
| Body prose, subtitles | Futura | `.menu-subtitle` in `gtasamenu.css` |
| HUD numerals | Pricedown | `font-pricedown` in the React HUD |

Every one of these faces is already vendored in the repo, so no new font is
downloaded and the split needs no new decisions. New prose styling reuses
Futura because that is what the recreation already uses for non-heading text.

This resolves the readability risk without diluting the theme, because it is
what the source material does.

## Asset Licensing

**Amended after implementation, at Maharsh's explicit direction.** The original
position was reference-only, nothing ships. Two textures now ship.

`back6.png` and `back7.png` are decoded from `models/fronten2.txd` by
`scripts/extract-txd.py` and live in `combined-gta/assets/game/`. They are the
only two menu backgrounds the fan recreation does not already include; the
others were extracted, compared at identical resolution, and deleted rather
than shipped for no gain.

These are Rockstar's copyrighted assets and the site is deployed publicly. That
tradeoff was raised twice and accepted. They are isolated in one directory with
a README documenting exactly how to remove them, so the decision stays
reversible in two edits.

The four combined projects are fan-made recreations, which is what makes them
distributable. `gtasamenu.css` reimplements the menu in CSS with free lookalike
fonts rather than shipping `fonts.txd`, and that property is preserved here.

`text/american.gxt` may be parsed locally to confirm exact menu wording. The
parsed output is not committed or published.

## Hosting

Deploy to `Maharsh17/Maharsh17.github.io`, which already exists and currently
holds only a LICENSE, a README, and the resume PDF. Already wired for GitHub
Pages, and leaves `janimaharsh.com` one CNAME away.

The resume PDF stays in place and gets linked from `missions.html`.

## Error Handling

- `site.js` already guards on a missing notification library and an absent
  section tag, and exits silently.
- Audio autoplay rejections are caught in both vendored libraries. Browsers
  block audio before a user gesture, so entry notifications are silent by
  design rather than by accident.
- If `projects.json` fails to load, save slots render from `overrides.json`
  alone. The page must not blank out.
- Private repos render as unlinked slots, never as broken links.

## Verification

1. Every page returns 200 from `python3 -m http.server`.
2. Every `href`, `src`, and CSS `url()` resolves (the existing audit loop).
3. `node --check` passes on all JavaScript.
4. Visual check on each page against the original recreation, confirming the
   ported pages are unchanged.
5. Every number on the rendered site traces to `projects.json` or the resume.

## Open Questions

- **Resume PDF versus restated content.** Both. `missions.html` carries the
  full mission log so the page stands alone and is indexable, and links the PDF
  as a download for anyone who wants the printable version. A themed page a
  recruiter cannot skim is worse than no page, and a PDF-only page is invisible
  to search.

Still open, both requiring facts only Maharsh has:

   It currently occupies a save slot with no outbound link.
2. Is `janimaharsh.com` meant to be replaced by this eventually, or stay
   separate? This changes nothing structurally, only whether a CNAME is added
   at the end.
